```sql
CREATE TABLE ohlcv_daily (
    time DATE NOT NULL,
    stock_code VARCHAR(6) NOT NULL,
    open_price INTEGER,
    high_price INTEGER,
    low_price INTEGER,
    close_price INTEGER,
    volume BIGINT,
    trading_value BIGINT,
    PRIMARY KEY (time, stock_code)
);

-- 시가총액
CREATE TABLE market_cap_daily (
    time DATE NOT NULL,
    stock_code VARCHAR(6) NOT NULL,
    market_cap BIGINT,
    PRIMARY KEY (time, stock_code)
);

-- 투자자별 순매수
CREATE TABLE investor_trading (
    time DATE NOT NULL,
    stock_code VARCHAR(6) NOT NULL,
    investor_type VARCHAR(20) NOT NULL,
    net_buy_value BIGINT,
    PRIMARY KEY (time, stock_code, investor_type)
);
```

## 📜 스크립트 상세

### scripts/load_all_data_from_csv.py

#### 주요 함수

**1. get_stock_mapping()**
- DB의 stocks 테이블에서 종목명 → 종목코드 매핑 로드
- 반환: `{"동화약품": "000020", "삼성전자": "005930", ...}`

**2. load_csv_pivot_to_list(file_path, stock_mapping)**
- CSV 파일 읽기 (Pivot 형식)
- `pd.melt()`로 정규화 변환
- 종목명 → 종목코드 매핑
- 반환: `[{"date": date, "stock_code": "000020", "value": 14800}, ...]`

**3. load_ohlcv_data(stock_mapping, temp_folder)**
- 6개 CSV 파일 읽기 (시가/고가/저가/현재가/거래량/거래대금)
- 각 파일의 데이터를 딕셔너리로 결합
- ohlcv_daily 테이블에 bulk insert
- ON CONFLICT DO UPDATE 사용 (중복 데이터 방지)

**4. load_market_cap_data(stock_mapping, temp_folder)**
- 1개 CSV 파일 읽기 (시가총액)
- market_cap_daily 테이블에 insert

**5. load_investor_data(stock_mapping, temp_folder)**
- 4개 CSV 파일 읽기 (외인/기관계/연기금/개인)
- investor_type 추가
- investor_trading 테이블에 insert

#### 성능 최적화 포인트

**핵심: df.melt() 사용**
```python
# ❌ 느린 방식 (30분+)
for idx, row in df.iterrows():
    for stock_name in df.columns[1:]:
        value = row[stock_name]
        # 처리...

# ✅ 빠른 방식 (5-7초)
df_melted = df.melt(
    id_vars=[date_col],
    var_name='stock_name',
    value_name='value'
)
# 벡터화 연산으로 한 번에 처리
```

**결과**: 300배 이상 속도 향상 (30분+ → 5초)

## 🔧 트러블슈팅

### 문제 1: ON CONFLICT 에러

**증상**:
```
there is no unique or exclusion constraint matching the ON CONFLICT specification
```

**원인**: PRIMARY KEY 미설정

**해결**:
```sql
ALTER TABLE ohlcv_daily ADD PRIMARY KEY (time, stock_code);
ALTER TABLE market_cap_daily ADD PRIMARY KEY (time, stock_code);
ALTER TABLE investor_trading ADD PRIMARY KEY (time, stock_code, investor_type);
```

### 문제 2: 매우 느린 실행 속도

**증상**: 첫 CSV 파일 읽기에 30분 이상 소요

**원인**: `df.iterrows()` 사용 (비효율적)

**해결**: 스크립트에서 이미 `df.melt()` 사용 중 (최적화 완료)

### 문제 3: 메모리 부족

**증상**: 대용량 CSV 파일 읽기 시 메모리 에러

**해결**: 현재 스크립트는 chunk 단위 처리 불필요 (19MB × 11개)

**향후**: 더 큰 파일 처리시 `pd.read_csv(chunksize=10000)` 고려

### 문제 4: 미매칭 종목

**증상**: 23개 종목이 stocks 테이블에 없음

**원인**:
- CSV 파일: 과거 상장된 종목 포함 (상장폐지 포함)
- stocks 테이블: 현재 상장 종목만 포함

**해결**:
- 무시: 상장폐지 종목은 스킵 (현재 방식)
- 또는: stocks 테이블에 과거 상장폐지 종목 추가

## 수정주가 query 가이드 (5/17~)

| 데이터 | raw | adjusted |
|---|---|---|
| 일봉 | `SELECT close_price FROM ohlcv_daily` | `SELECT adj_close FROM ohlcv_daily` |
| 분봉 | `SELECT close FROM ohlcv_intraday` | `SELECT close FROM ohlcv_intraday_adjusted` (view, 자동) |

분봉 view는 raw × adj_factor 자동 곱셈 + volume은 raw 유지 + raw_* 별도 노출.
corporate_actions 테이블에서 이벤트 발생 종목 + 일자 + factor 조회 가능.

**⚠️ ETF NAV 계산 시 반드시 `close_price` (raw) 사용 — `adj_close` 금지.** PDF shares는 실물 주수라 수정주가를 곱하면 corporate action 발생일에 NAV가 튀어버림.
