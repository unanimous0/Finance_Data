## 외국인 지분율은 02:00 아닌 08:30 수집 (2026-06-02~)

**인포맥스 외인 데이터는 T일분이 T+1 새벽 05:30 이후 등록.** 02:00 본체는 빈 응답이라 항상 실패 → `get_update_range`가 ohlcv 기준으로 날짜를 전진시켜 **못 받은 외인이 영구 누락**되던 사고(5/22~6/1 10일 누락). 해결:

- **02:00 본체**: `run_update(collect_foreign=False)` — 외인 STEP skip
- **08:30 아침 종합 보충** (`job_etf_snapshot` 안): ETF 스냅샷 다음에 `run_supplement_pipeline()` 호출
  - 데이터별 마지막 적재일 ~ 어제 영업일을 검토 (최근 3영업일 무조건 + 가장 뒤처진 테이블 last+1, 상한 10일)
  - 각 날짜 `run_update(missing_only=True, sync_master=False)` → 외인 + OHLCV/수급 누락 종합 보충
  - `sync_master=False`로 마스터 갱신(~55초) 보충 루프 중복 제거
- **외인은 1일 지연**으로 들어옴 (T일 외인은 T+1 08:30). 정상.

→ 외인·ETF PDF 둘 다 "당일 새벽 인포맥스 미등록 → 늦게 등록" 같은 부류라 08:30 한 잡에 통합. daily_update에 합치면 02:00 프로세스가 08:30까지 idle 점유하므로 분리 유지.

## daily_update 요일별 동작

`get_update_range()`가 `end = last_business_day_on_or_before(어제)`로 잡으므로:

| 요일 02:00 | 어제 | 동작 |
|---|---|---|
| 토 | 금(영업일) | 금요일 데이터 정식 수집 (~1.5~4h) |
| 일 | 토(휴장) | `skipped_no_data` → 즉시 종료 + 배당/휴일/지수구성/지수선물/수정주가 파이프라인만 짧게 진행 |
| 월 | 일(휴장) | 동일하게 `skipped_no_data` (월요일 데이터는 화 02:00에 받음) |
| 화~금 | 전일(영업일) | 정식 수집 |

→ 일요일 02:00은 사실상 no-op이라 03:00 백업 / 03:30 상장주식수와 시간 겹침 없음.

## ETF snapshot의 today + yesterday 2-pass

같은 실행 안에서 `run_etf_daily_snapshot_pipeline`을 두 번 호출:
1. `target_date = today_kst`
2. `target_date = yesterday(=직전 영업일)`

**이유**: 인포맥스 ETF PDF는 ingest 지연으로 당일 데이터가 늦게 settled되는 케이스가 있음. 다음날 yesterday pass가 UPSERT(`ON CONFLICT ... DO UPDATE SET`)로 덮어쓰면서 정정.

→ **차이 발생 시 다음날 yesterday pass의 값이 정답.**

### ETF PDF는 왜 02:00에 같이 안 받고 08:30?
02:00 시점엔 인포맥스가 당일 ETF PDF 데이터 ingest 미완 (KODEX 200 등 빈 응답 실측). 09시 이후 정상 반환 → 안전 마진 두고 08:30.

## ETF snapshot의 daily_update 대기 로직 (`wait_for_daily_update`)

08:30 cron 시점에 daily_update가 아직 진행 중이면 인포맥스 충돌 회피를 위해 대기:

| 단계 | 동작 | 최대 시간 |
|---|---|---|
| 1단계 | 60s polling, daily_update 종료 즉시 재개 | 4h |
| 2단계 | 2h 간격 deep retry, 매 2시간마다 pgrep 재확인 | 6h (2h × 3) |
| 최종 | 진행 중이면 `RuntimeError` abort | 합계 10h |

abort 시점은 18:30 마지노선. 다음날 yesterday 2-pass로 부분 회수 가능.

→ 08:30 ~ 18:30 사이엔 다른 반복 잡 없어 retry 동안 충돌 없음. abort 시점도 23:30 stockfut / 02:00 daily_update 이전이라 안전.

코드: `scripts/etf_snapshot.py:31-77` (`WAIT_POLL_TIMEOUT_SEC=4h`, `DEEP_RETRY_INTERVAL_SEC=2h`, `DEEP_RETRY_MAX=3`).

## stockfut_today 휴장일 skip + LS t8406 fallback 방어

**LS t8406은 휴장일 query 시 직전 영업일 데이터를 반환**한다 (5/25 부처님오신날에 5/22 데이터가 5/25로 적재된 사고). 이중 방어:

1. `job_stockfut_today`가 시작 시 `is_market_closed(today)` → true면 즉시 skip + noop 알림 (사유 포함)
2. `_verify_stockfut_loaded`가 적재 후 직전 영업일과 close/volume 100% 동일하면 fail 판정 (fallback 감지)

→ 6/3 지방선거일에 정상 skip 확인 (stockfut 0건). 또 historical 불가라 받은 후 검증 실패 시 5분 간격 3회 재시도.

## sync_stock_master 오비활성 방어 (ghost_delist 가드)

`sync_stock_master`는 인포맥스 `get_stock_codes`/`expired` 둘 다에 없는 활성 종목을 비활성(ghost_delist)한다. 인포맥스가 종목을 **부분 누락** 반환하면 정상 종목이 오비활성됨 (2026-06: ETF 191개 오비활성 → OHLCV 8일 누락 사고).

이중 가드:
1. `api_coverage >= 0.9` — API 반환이 DB 활성의 90% 미만이면 전체 skip (대량 누락 차단)
2. `GHOST_DELIST_MAX=20` — ghost 후보가 20개 초과면 부분 누락 의심하고 비활성 skip + errors 기록(알림)

→ OHLCV는 유형 구분 없이 활성 ETF 전부 수집 (`get_stocks(include_etf=True)`). etf_snapshot PDF만 국내형 필터 — 별개 정책.

### 재시작 전 절대 체크

```bash
pgrep -f "daily_update|backfill_"                                  # 별도 프로세스 job
tail -40 logs/scheduler.log | grep -E "Running job|executed successfully" | tail -4   # in-process job
```

**pgrep 허점(2026-06-26 실측)**: 08:30 종합보충·02:00 daily_update는 daily_scheduler **in-process 함수**라 pgrep에 안 잡힌다. 반드시 로그로 진행 중 job(짝 없는 `Running job`) 확인.

**graceful shutdown 작동함**: `C-c` 받으면 `신호 2 수신 → 진행 중 job 완료 대기 후 종료`로 실행 중 job을 끝까지 기다린 뒤 종료(데이터 안전). 08:30 supplement 중 재시작하면 ~1h 대기 후 종료되니 가능하면 job 없을 때.
